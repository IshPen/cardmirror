Guided walkthrough

Set up CardBridge in about 20 minutes

A free, always-on, end-to-end-encrypted collaboration relay for your debate team — plus this dashboard to watch it all. Three places to visit: a database, a relay, and this dashboard. Follow along; tick each step as you go and your progress is saved.

💳 No credit card 🔒 End-to-end encrypted ⏱ ~20 minutes
1

Create your database

Supabase · ~7 min
  1. Go to supabase.com → New project. Pick a name and a strong database password — save that password, you'll need it in step 2.
  2. When it's ready (~2 min), open Project Settings → Database → Connection string and select the Session pooler tab. Copy that URI and replace [YOUR-PASSWORD] with your DB password.
  3. Open SQL Editor → New query, paste all of setup.sql, and click Run. (Safe to re-run.)
⚠If your connection string doesn't say pooler, you have the wrong one. This is the single most common setup mistake.
2

Deploy the relay

Render · ~10 min

Click the button, point Render at the repo, and paste your Session-pooler string when it asks for DATABASE_URL:

  1. Render reads render.yaml and proposes one free web service. It prompts for DATABASE_URL — paste the pooler string from step 1. It generates a random RELAY_TOKEN for you.
  2. Click Apply / Deploy. Wait until it shows Live and the health check passes.
  3. Note two values: your Relay URL (service URL + /relay) and, from Environment → RELAY_TOKEN, your relay token.
◆Private repo? The one-click button needs a public repo — otherwise use Render → New → Blueprint and point it at your fork.
3

Keep it awake

UptimeRobot · ~5 min · optional

Render's free tier sleeps after ~15 min idle and takes ~60s to wake — long enough to look broken mid-round. A free pinger prevents it.

  1. Sign up at uptimerobot.com → Add New Monitor → type HTTP(s).
  2. URL = your relay URL + /health (e.g. https://…onrender.com/relay/health). Interval = 5 minutes. Save.
4

Open the dashboard & connect

~3 min

Open this dashboard's URL. If it's your first time, a guided wizard appears. Fill each step and hit its Test button — it live-checks the connection before you save.

  • Supabase — Project URL + anon key (Project Settings → API). Never the service-role key.
  • Relay — the relay URL from step 2 (ends in /relay).
  • Dashboard token — paste your RELAY_TOKEN, or Generate one and add it to the relay's tokens.
⚠Everything you enter stays in your browser (localStorage). The anon key is public by design; a connection string in the browser would be a public database — never paste one here.
5

Sign in to sync

coach account · ~2 min

The coach account is what carries your tokens, document keys and shared code to any device. Create it once, then sign in.

  1. In Supabase → Authentication → Users → Add user. Enter an email + password and tick Auto Confirm User.
  2. Back in the dashboard's wizard step 4 (Coach account), enter that email + password and hit Sign in & sync (or use the Sign in chip in the header later).
  3. The header's sync chip turns green “Synced”. On a new device, just sign in with the same account and everything restores.
◆Your password is never stored — it derives the key that encrypts your vault, so you re-enter it each session to unlock sync. That's what keeps your data private even from Supabase.
6

Point CardMirror at your relay

~2 min per machine

On each teammate's CardMirror desktop (the full build — CardMirror Lite has no collaboration):

  1. Open Settings → Collaboration.
  2. Paste the Relay URL and that machine's relay token.
  3. Everyone must run the same CardMirror version — older builds can't read the current session format.
7

Share to students & open docs

~2 min

So the dashboard can open a document, a student invites the dashboard's member code — the same invite flow they already use.

  1. Open the Member panel → Copy code. Optionally turn on “Use one code across my devices” so students invite it just once.
  2. A student invites that code in CardMirror. The dashboard learns the doc's name and gets its key — now an Open button appears on that session.
  3. Open it to view/edit with native styling, go live, export, or send notes.
